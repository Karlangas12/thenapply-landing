mcp-auth-kit

The MCP OAuth token lifecycle, fixed where it actually breaks.

mcp-auth-kit wraps the OAuthClientProvider you already have from @modelcontextprotocol/sdk and returns another one — same interface, same call sites — with auto-refresh and a TTL fallback, retried dynamic client registration, issuer-bound refresh, and a correctly normalized resource parameter. Where the unwrapped path fails silently, it raises an actionable error instead.

ESM-only, for now. The package ships as "type": "module" with only an import condition in its exports map. There is no CommonJS build yet, so require() from a CJS project will not resolve it.

WHAT IT FIXES

Four token-lifecycle failures

Each one started as a real, open issue in somebody else's MCP client — not a hypothetical. Each one is pinned by a unit test that first reproduces the failure against an unwrapped provider, then proves the fix.

Silent expiry

The token response omits expires_in, so nothing tracks expiry and the client keeps using a dead token. mcp-auth-kit refreshes proactively using a configurable fallback TTL, and clamps a server-supplied expires_in to a sane range before trusting it.

anthropics/claude-code#26281

Registration fails without retry

A transient failure during RFC 7591 dynamic client registration surfaces as "dynamic client registration not supported" and stops there. mcp-auth-kit retries with exponential backoff — but only for failures that are actually transient (network errors, server_error, 429).

openai/codex#13200

Malformed resource

A trailing slash on the resource indicator breaks auth against Microsoft Entra ID. mcp-auth-kit normalizes it before the refresh call, so the same configuration works either way.

anthropics/claude-code#52871

A refresh token that is never used

The client holds a valid refresh_token and never calls the refresh grant with it. mcp-auth-kit does — and binds it to the issuer, refusing to send a refresh token or client credentials to the wrong authorization server.

openai/codex#17265
EVIDENCE

Not one client's bug — a pattern

The four issues above were open, unresolved and older than 30 days when the package was written (verified 2026-09-29). The same class of failure — MCP client OAuth token lifecycle — has also been reported against four more codebases, which is why the fix lives in a wrapper rather than in a patch to any one client.

Seven rounds of adversarial review

Before publishing, the package went through seven rounds of adversarial review with Opus, each from a fresh session so no round inherited the previous one's assumptions. The commit history is deliberately unsquashed, so each round's findings and the fixes they produced are traceable in it. Three of the tests are drift guards rather than feature tests — they fail when @modelcontextprotocol/sdk changes behaviour the wrapper depends on.

INSTALL

Free, MIT, no account

Nothing to buy and no key to request. Install it, wrap the provider you already have, and pass the result anywhere the unwrapped one was accepted.

npm install 
npm install @karlangas12/mcp-auth-kit @modelcontextprotocol/sdk

@modelcontextprotocol/sdk is a peer dependency, so it is listed here explicitly — the package itself has no runtime dependencies of its own.

TypeScript / wrapOAuthClientProvider 
import { wrapOAuthClientProvider } from '@karlangas12/mcp-auth-kit';
import { StreamableHTTPClientTransport } from '@modelcontextprotocol/sdk/client/streamableHttp.js';

// `myProvider` is whatever OAuthClientProvider you already have —
// in-memory, filesystem-backed, keychain-backed, etc.
const authProvider = wrapOAuthClientProvider(myProvider, {
  authorizationServerUrl: 'https://auth.example.com',
  resource: 'https://mcp.example.com/mcp', // trailing slash normalized either way
  fallbackTokenTtlMs: 55 * 60 * 1000, // used only when the server omits expires_in
  registration: { maxAttempts: 5, baseDelayMs: 250 }, // opt in to retried DCR
});

const transport = new StreamableHTTPClientTransport(
  new URL('https://mcp.example.com/mcp'),
  { authProvider },
);
